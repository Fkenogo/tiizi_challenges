## Scope and source behavior

- Canonical code definition: `src/data/wellnessActivitiesCatalog.ts`.
- Runtime behavior: `src/services/wellnessActivityService.ts` reads the Firestore `wellnessActivities` collection first. If that collection is empty or a supported read error occurs, it returns the local canonical catalog.
- Seed behavior: `scripts/seedWellnessActivities.ts` deletes Firestore documents absent from the local catalog and upserts every evaluated catalog activity.
- Lifecycle metadata behavior: `scripts/backfillCatalogTemplateFields.ts` can add `status`, `visibility`, `isPublished`, and `sortName` to Firestore documents. Those values are not defined per activity in the canonical catalog and therefore are not inferred into the table.
- Search behavior: no `searchKeywords` field is defined in the canonical activity objects. Runtime local search checks `name`, `description`, `shortName`, and `tags`; the Search Keywords column is therefore `—` for every row.
- `Colour / Theme` and `Default Challenge Duration` are not stored on canonical wellness activity objects; their cells are `—`.
- `createdAt` and `updatedAt` are absent from the canonical catalog. The seed script adds timestamps at execution time, so no timestamp values are inferred here.
- The prototype array in `wellness-challenge-form.html` is not imported by the application and is not treated as a canonical source.

# Content Generation and Template Mechanisms

`buildActivity(category, seed)` evaluates each activity seed and generates or defaults the following fields:

- `id`: `${category}-${slugify(shortName || name)}`
- `description`: default template exists, but every current activity seed explicitly stores a description.
- `icon`: inherited from `categoryMeta`.
- `activityType`: inherited from `categoryMeta` unless overridden by the activity seed.
- `targetType`: defaults to `daily`, although every current seed explicitly stores a target type.
- `suggestedFrequency`: defaults to `1`.
- `protocolSteps`: all current activities inherit the default three-step protocol, with the first step interpolating the lower-cased `shortName`.
- `benefits`: 64 activities inherit category-based default benefits; Steps, Yoga, and Meditation explicitly store custom benefits.
- `guidelines`: 65 activities inherit the default guideline set; Blood Pressure Check and Medication Adherence explicitly store custom guidelines.
- `warnings`: stored only when supplied by a seed. Blood Sugar Check is the only current activity with a warning.
- `defaultPoints`: fixed at `10`.
- `bonusConditions`: fixed to `7-day consistency streak` (50 points) and `Challenge completion` (150 points).
- `popular`: generated as `difficulty === 'beginner'`.
- `medicalSupervisionRequired`: generated as `Boolean(seed.medicalSupervisionRequired)`.
- `tags`: defaults to `[category, shortName.toLowerCase(), difficulty]`; every current activity inherits this template.

For every inherited value, the master table contains the evaluated value exactly as returned by the catalog and labels its origin in the Content Generation / Template Inheritance column.
