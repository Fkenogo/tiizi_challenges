# Phase_4.0_Tiizi Reference_Knowledge_Object

**Status:** Knowledge Production Standard

---

## Mission

Create one knowledge object that demonstrates every capability of the Tiizi Knowledge Platform.

Everything we have designed so far must be visible inside one object.

If something cannot be represented inside this object, then either:

- our architecture is incomplete, or
- the information belongs somewhere else.

The RKO therefore becomes the ultimate validation of the platform architecture.

---

# Why Push-up?

Because Push-up exercises almost every part of the model:

It has:

- regressions
- progressions
- variations
- equipment options
- measurable performance
- challenge suitability
- workout suitability
- AI recommendations
- learning content
- safety considerations
- graph relationships
- multilingual terminology

It is rich enough to validate the entire platform.

---

# The RKO Validation Rule

Every future knowledge object should answer the question:

> "Does it meet the Push-up Standard?"
>

The Push-up record becomes Tiizi's equivalent of:

- a reference implementation in software engineering,
- a canonical specimen in biology,
- a style guide example in publishing.

---

# Structure of the Reference Knowledge Object

Rather than treating it as a long flat record, I recommend modelling it as interconnected modules.

```
Reference Knowledge Object
│
├── Identity
├── Taxonomy
├── Scientific Profile
├── Performance Profile
├── Learning Profile
├── Safety Profile
├── Programming Profile
├── Challenge Profile
├── Recommendation Profile
├── Graph Profile
├── AI Profile
├── Governance Profile
└── Media Profile
```

Each profile is independently governable.

Regressions

# AI Profile

The AI Profile tells intelligent systems how to reason about the object.

Examples:

Intent Categories:

- Learn
- Improve Technique
- Build Strength
- Beginner
- Rehabilitation Progression

Recommendation Triggers:

- No Equipment
- Upper-body Goal
- Short Workout
- Challenge Participation

Confidence Modifiers:

- Verified Completion
- Repeated Success
- Existing Shoulder Limitation

Importantly, this profile should guide AI behaviour without redefining the underlying exercise knowledge.

---

# Media Profile

The reference object should also define media standards rather than treating media as an afterthought.

Recommended assets include:

- Primary demonstration image
- Start position image
- End position image
- Side profile image
- Common mistake illustration
- Short instructional video
- Accessibility-friendly captions
- Alt text for every image

Media becomes part of the governed knowledge, not just supporting content.

---

# The "Knowledge Passport"

One concept I would introduce is a **Knowledge Passport**.

Every canonical knowledge object receives a concise summary that any subsystem can consume.

For Push-up, it might include:

- Canonical ID
- Version
- Primary family
- Primary metric
- Safety tier
- Difficulty
- Challenge compatibility
- Relationship count
- Translation coverage
- Review status

This acts as a lightweight identity card while the full knowledge object remains the authoritative source.
