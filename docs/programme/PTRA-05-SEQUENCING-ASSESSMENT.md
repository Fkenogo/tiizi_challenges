# PTRA-05 — Sequencing Assessment

**Programme:** Tiizi Version 2 — Stage E0

**Document type:** Programme sequence assessment

**Status:** Recommendation only; no authorization

**Assessment date:** 2026-07-25

## 1. Purpose

This assessment determines whether the remaining frozen Blueprint order should be preserved, simplified, merged or transitioned into a final consolidation programme.

It changes no Blueprint order and authorizes no work.

## 2. Options Assessed

### Option A — Preserve Every Remaining Deliverable as a Separate Package

This would create separate bounded packages for deliverables 15 through 20.

**Strength:** Direct one-to-one correspondence with Blueprint numbering.

**Weakness:** Deliverables 17 through 20 are integration outputs rather than independent constitutional subjects. Treating them as separate constitutional packages would multiply review boundaries and risk creating doctrine from documentary functions.

**Assessment:** Not recommended.

### Option B — Merge All Remaining Work into One Final Package

This would combine Governance Index and Status Integrity, Validation Rules and integration.

**Strength:** Minimizes package count.

**Weakness:** Validation depends on completed status-integrity treatment, and integration depends on all substantive subjects. Combining them would blur dependency gates, complicate proposition traceability and invite scope expansion.

**Assessment:** Not recommended.

### Option C — Preserve Two Bounded Subjects, Then Consolidate

This would:

1. preserve Governance Index and Status Integrity as one bounded constitutional subject;
2. preserve Validation Rules as one later bounded constitutional subject; and
3. merge Blueprint deliverables 17–20 into one final consolidation programme.

**Strength:** Preserves substantive Blueprint order, dependency integrity and one-subject drafting while avoiding artificial fragmentation of integration work.

**Weakness:** Requires two further governed planning and authorization cycles before consolidation.

**Assessment:** Recommended.

### Option D — Transition Directly to Final Consolidation

This would treat the partial index and validation evidence as sufficient.

**Strength:** Shortens the sequence.

**Weakness:** Leaves GAP-16, GAP-17 and CON-08 without dedicated treatment and would require consolidation to invent missing doctrine.

**Assessment:** Rejected.

## 3. Dependency Logic

The recommended sequence is constitutionally and architecturally necessary:

```text
Historical Preservation
        ↓
Governance Index and Status Integrity
        ↓
Validation Rules
        ↓
Final CGP-02 Consolidation
        ↓
Whole-Instrument Founder Review and Approval
        ↓
Separately Attributable Adoption Treatment
        ↓
CGP-02 Programme Transition
```

Historical Preservation is complete. It supplies the current-versus-historical boundary needed by status representations.

Governance Index and Status Integrity must precede Validation Rules because validation must assess the integrity rule rather than invent it.

Validation Rules must precede consolidation because the integrated draft requires a complete validation basis.

## 4. Simplification Assessment

The Blueprint should be simplified only at the integration layer:

- deliverable 17 supplies consolidated deferrals;
- deliverable 18 supplies integrated status and decision trace;
- deliverable 19 supplies genuinely unresolved final Founder questions; and
- deliverable 20 supplies whole-draft validation.

These should be outputs of one consolidation programme, not merged into constitutional doctrine and not treated as four standalone constitutional subjects.

No simplification is justified for deliverables 15 or 16.

## 5. Completed-Package Consolidation Controls

The final consolidation programme must:

- preserve proposition wording unless an attributable correction is separately authorized;
- preserve every proposition identifier or provide an explicit crosswalk;
- preserve each package’s recorded status;
- preserve all Founder decisions and dates;
- retain subject-specific non-effects where they protect distinct boundaries;
- avoid treating recurring drafting practice as doctrine;
- avoid normalizing historical metadata;
- avoid resolving an instrument-specific conflict;
- create no Authority or accountability allocation; and
- produce no adoption or constitutional effect.

## 6. Sequencing Verdict

**Preserve, then consolidate.**

The optimal sequence is:

1. Governance Index and Status Integrity;
2. Validation Rules;
3. one final consolidation programme for deliverables 17–20;
4. whole-instrument review and Founder approval;
5. separately attributable adoption and constitutional-effect treatment; and
6. programme transition.

This verdict recommends sequence only. It does not establish identifiers, create planning packages or authorize drafting.
