## 4. Prerequisites Before Authorization

Before a Founder authorization decision is sought:

1. define one bounded subject: Supersession Rules;
2. distinguish supersession from amendment, adoption, conflict disposition, retirement, withdrawal and rejection;
3. preserve that records, labels, indexes and repository actions cannot create supersession by implication;
4. identify the constitutional questions concerning attributable supersession, bounded replacement scope, current and historical treatment, and evidence;
5. exclude actual supersession of any existing instrument;
6. exclude governance-index synchronization, implementation and repository procedure;
7. verify dependencies and source statuses;
8. preserve every Founder question as unresolved;
9. define bounded Founder Review deliverables;
10. complete the Founder Authorization Validation Checklist; and
11. synchronize the Master Programme only after attributable Founder authorization.

## 5. Planning Risks and Required Controls

| Risk | Planning control |
|---|---|
| Supersession inferred from a later approval or adoption | Require the planning boundary to examine supersession as a distinct attributable constitutional treatment. |
| Conflict disposition treated as automatic supersession | Preserve CGP-02C.7’s explicit deferral and separate the concepts. |
| Supersession collapsed into retirement, withdrawal or rejection | Keep Blueprint deliverable 13 outside the package. |
| Current-index representation treated as constitutive | Defer Governance Index and Status Integrity; distinguish constitutional act from representation. |
| Historical governance erased | Preserve historical intelligibility and attributable scope. |
| Authority or recorder allocation inferred | Use existing Governance Authority only and allocate no actor or relationship. |
| Implementation detail introduced | Exclude repository operations, file movement, storage, publication and tooling. |

These are planning controls, not constitutional answers.
