**Working package:** Tiizi V2 Activity Content & Catalogue Definition\

**Status:** Founder/Product working baseline --- representative-set
selection\
**Purpose:** Stress-test Sections 01--05 against real canonical Activity
candidates from the Founder Working Baseline before bulk catalogue

## 1. Source Baseline

The representative set is selected from the settled Tiizi V2 Initial
Canonical Activity Founder Working Baseline, not invented as a parallel
catalogue.

That baseline contains 118 canonical Activity candidates: - 84
Fitness; - 34 Wellness; - six Fitness categories; - six Wellness
categories.

The baseline is an initial governed candidate set rather than a
requirement that all 118 must become launch-ready simultaneously.

The representative catalogue exists to test the content model before
scaling.

## 2. Important Finding From the First Stress Test

The source baseline confirms **six** governed Metrics:

1.  Completion
2.  Repetitions
3.  Duration
4.  Distance
5.  Weight
6.  Quantity

Section 02 initially carried only five measurement families and omitted
**Weight**.

That was a genuine gap exposed by testing the standard against the real
baseline. Section 02 has therefore been corrected to include Weight
rather than forcing loaded Fitness Activities into Repetitions or
Quantity.

This is exactly the purpose of the representative-catalogue phase: real
Activities are allowed to correct the abstract standard before
catalogue-scale authoring.

## 3. Selection Principles

The representative set should not merely contain the most familiar
Activities.

It should collectively test:

-   repetition semantics;
-   static duration;
-   distance;
-   multiple compatible Metrics;
-   Weight/load;
-   Quantity;
-   equipment;
-   adaptation/variant boundaries;
-   protocol-based Wellness;
-   completion semantics;
-   self-attestation;
-   health-adjacent quantity;
-   safety/publication dependencies.

A representative Activity may test several of these at once.

## 5. Why These Ten

The set intentionally combines straightforward and difficult cases.

**Push-Up** tests whether Tiizi can explain technique and counting
without implying verification.

**Plank** tests whether Duration needs clear timing boundaries.

**Running** tests whether a largely self-evident Activity can remain
concise rather than being padded with unnecessary content.

**Bench Press** exposed the missing Weight family and tests whether
Repetitions and Weight remain distinct rather than becoming an ambiguous
combined value.

**Farmer Carry** is a stronger compatibility test because the source
baseline permits Distance, Duration and Weight. It will help distinguish
an Activity's permitted measurement dimensions from how a Challenge
Definition may combine them.

**Breathing Practice** tests protocol and completion content.

**Water Intake** tests Quantity semantics without allowing Tiizi to
invent a universal health target.

**Sleep** tests self-reported Duration and Completion and forces us to
define what the participant is actually reporting.

**Bedtime / Wake Time** tests the Activity--Challenge boundary: the
canonical Activity should not hard-code a bedtime or wake time merely
because a Challenge later asks a participant to meet one.

**Fasting** is intentionally not selected as an easy publication
candidate. It tests whether the catalogue can correctly keep an Activity
Draft/not Challenge Eligible when its meaning and safety dependencies
are unresolved.

## 6. Representative Set Is Not Automatic Publication

Selection into this section does not mean an Activity is:

-   fully authored;
-   Published;
-   Challenge Eligible;
-   approved for launch.

Each Activity must still be authored and reviewed against Sections
01--05 and the applicable KCS minima.

The representative set may produce different dispositions:

-   Publication-ready + Challenge Eligible;
-   Publication-ready but not yet Challenge Eligible;
-   Draft --- more content required;
-   Draft --- safety/product decision required;
-   reconsider canonical identity/variant relationship.

A failed exemplar is useful evidence if it reveals a weakness in the
model.

## 7. Authoring Template for Each Representative Activity

Each representative Activity should be worked through using this compact
structure.

### A. Identity

-   Activity Code
-   Canonical title
-   Domain
-   Category
-   Classification/subcategory where useful

### B. Meaning

-   Authoritative description
-   Purpose/context where useful
-   Semantic distinction from related Activities

### C. Measurement Contract

For each supported Metric: - Metric - exact permitted Unit(s) - what the
value/action means - participant reporting instruction

### D. Applicable Guidance

Fitness, as relevant: - setup - execution - form cues - common
mistakes - equipment/environment - adaptations

Wellness, as relevant: - preparation - protocol - session framing -
completion meaning - semantic guidance

### E. Safety / Caution

-   proportionate ordinary caution
-   unresolved safety dependency, if any
-   prohibited clinical/unsupported claims to avoid

### F. Challenge Boundary Check

Confirm that the Activity does not encode: - target; - frequency; -
schedule; - Challenge duration; - Challenge type; - scoring; -
ranking; - streak rule; - recognition/reward.

### G. Readiness

Record separately: - content status: Draft / publication-ready; -
lifecycle: Draft / Published / Retired when later governed; - Challenge
eligibility: Eligible / Not Eligible / Pending; - unresolved
dependencies.

## 8. Authoring Order

The recommended order is:

1.  Push-Up
2.  Breathing Practice
3.  Running
4.  Water Intake
5.  Plank
6.  Sleep
7.  Bench Press
8.  Farmer Carry

The first four should be enough to test the main Fitness/Wellness
content shapes before deeper authoring.

The later Activities deliberately introduce harder compatibility and
safety questions.

## 9. Catalogue-Scale Gate

Do not bulk-author the remaining catalogue merely because these ten
files exist.

Before scaling, review the representative set and answer:

-   Did any real Activity require a missing content module?
-   Did any real Activity require a missing Metric?
-   Are exact Metric/Unit tuples sufficient?
-   Does the Fitness/Wellness split remain useful?
-   Are adaptations and separate canonical Activities distinguishable?
-   Can Completion be explained without collapsing it into Challenge
    Done?
-   Can health-adjacent Activities remain useful without clinical
    claims?
-   Are some baseline candidates unsuitable for initial publication?
-   Does Challenge Definition need a capability not present in canonical
    Activity Knowledge?

Only after this review should Tiizi establish the catalogue-scale
authoring plan.

## 10. Immediate Next Work

Begin full product authoring of the first representative Activities
rather than adding more abstract standards.

The first exemplar is **FIT-STR-001 Push-Up**, followed by **WEL-MND-003
Breathing Practice**.

Their existing PF-01 seeded content is engineering evidence and a useful
draft source, not automatically final Founder-approved catalogue
wording.
